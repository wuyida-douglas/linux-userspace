5.1 交付格式
  交付产品为可运行的容器化架构靶场。靶场应适配 harbor 框架，并能够通过 harbor 完成环境启动、Agent运行和任务评测。
每个靶场通常由多个 Docker 容器组成，分别模拟攻击者主机和目标系统，并通过隔离的 Docker 网络进行通信。
harbor 用于在隔离的容器化环境中评测Agent，项目地址为：https://www.harborframework.com/
  单个任务目录：每个靶场任务应以独立目录交付
<CVE-ID>/
  ├── images/
  │   └── *.tar.gz                         # 单个任务所需 Docker 镜像打包
  │
  └── harbor-runtime-profile/              # harbor框架下 任务运行需要的各种配置
      ├── task.toml                        # 任务 ID、类型、镜像等元数据
      ├── instruction.md                   # 提供给 Agent 的提示词
      ├── environment/
      │   ├── docker-compose.yaml          # 服务、镜像、网络和挂载配置
      │   └── assets/                     # 提供给 Agent 的题目材料（可以包括poc.sh,entrypoint.sh,取决于具体的靶场配置）
      └── tests/
          └── test.sh                      # 任务验证和评分脚本

  批量交付目录：如果需要批量交付多个任务，可以在任务目录外增加 Bundle 层：
 <bundle>/
  ├── bin/
  │   ├── load_image.py                  # 加载指定任务镜像
  │   └── load_shared_images.py          # 加载全部共享镜像
  │
  ├── _runtime/  # 共享运行时镜像，该位置用于放置多个任务复用的镜像，例如评测使用的Agent所在的镜像，加快并发测试速度。
  │   ├── agent-python-pwn-3.12.tar.gz
  │   ├── ...
  │   └── ubuntu-22.04.tar.gz
  │
  ├── <task-id-1>/                       # 单个任务目录
  │   ├── images/
  │   └── harbor-runtime-profile/
  │
  └── <task-id-2>/
      ├── images/
      └── harbor-runtime-profile/


  备注：
交付时，environment/ 下通常不需要提供 Dockerfile。所有运行所需镜像应以 Docker 镜像归档文件（如 .tar.gz）交付，并通过 docker load 导入本地 Docker 镜像仓库。只有在不提供镜像压缩包，希望根据源码重新构建docker，动态安装依赖时，才需要 Dockerfile（提供Dockerfile构建就会产生网络下载行为）。

镜像压缩包 / 镜像归档文件应包含 docker-compose.yaml 中引用的所有镜像，并且在 task.toml 中对于docker-compose.yaml 中引用的所有预构建的镜像，必须进行声明。
    对于Agent所在的镜像，可以放置于_runtime/，以公共镜像的方式load，减少重复打包和重复加载的开销。
    注意，如果 task.toml 没声明预构建 Agent 镜像，harbor 就强制使用 docker-compose-build.yaml，从而寻找不存在的 Dockerfile。

5.4 启动脚本
  每个评测任务应提供以下两个脚本：
镜像加载与 Harbor 环境准备脚本；
Harbor 评测启动脚本。

  镜像加载与环境准备脚本：
export NAME="ctf-browser-krautflare"

export BASE="/mnt/shared-storage-gpfs2/trustcyberdata/private/CVEDockerGen/wuxuansheng/20260915_test"
export TASK_DIR="$BASE/$NAME"
export RUNTIME="$TASK_DIR/harbor-runtime-profile"

# 共享镜像通常只需在首次使用时加载一次
# 外层 .tar.gz包含两种格式，一种解压为.tar；另一种解压为 pre.tar 和 post.tar，两种格式均支持
python3 "$BASE/bin/load_shared_images.py"

# 加载当前任务的专属镜像
python3 "$BASE/bin/load_image.py" --task "$NAME"
  环境准备完成后，任务运行目录为： <bundle>/<task-id>/harbor-runtime-profile/

Harbor 评测启动脚本
export CLAUDE="/mnt/shared-storage-gpfs2/trustcyberdata/public/agent_bundles/claude-code-2.1.228-linux-amd64/claude"
export JOBS_DIR="/data/Harbor/jobs"

# 建议通过环境变量或 --env-file 提供真实 API Key，
export ANTHROPIC_API_KEY="<your-api-key>"
export ANTHROPIC_BASE_URL="<your-api-url>"

harbor run \
    --path "$RUNTIME" \
    --agent claude-code \
    --model <model_name> \
    --ak version=<model_version> \
    --ak max_turns=<max_turns> \
    --ak reasoning_effort=max \
    --agent-timeout-multiplier <max_time> \
    --mounts "[{\"type\":\"bind\",\"source\":\"$CLAUDE\",\"target\":\"/usr/local/bin/claude\",\"read_only\":true}]" \
    --ae ANTHROPIC_API_KEY="$ANTHROPIC_API_KEY" \
    --ae ANTHROPIC_BASE_URL="$ANTHROPIC_BASE_URL" \
    --ae NO_PROXY="localhost,127.0.0.1,$ANTHROPIC_BASE_URL" \
    --ae no_proxy="localhost,127.0.0.1,$ANTHROPIC_BASE_URL" \
    --ae CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT=1 \
    --n-attempts 1 \
    --n-concurrent 1 \
    --jobs-dir "$JOBS_DIR" \
    --job-name "$NAME-claude-$(date +%Y%m%d-%H%M%S)" \
    --yes
