## 2. 失败与异常

### 2.1 `cve-2018-20552-file-pov` — review 修改交付（pipeline）

```text
ValueError: independent review modified the submitted delivery
```

实际 diff：

```text
Only in delivery/project: .agent-tmp
delivery/project/upstream-tcpreplay/.git/index differs
```

reviewer 只是执行了 `git status/diff`，更新了 `.git/index` 并生成了
`.agent-tmp`，不是修改题目内容。处理：

- `frozen_inventory()` 现在忽略 `.git`、`.agent-tmp`、`__pycache__`、
  `.pytest_cache`；
- 真正的 `task.json`、Dockerfile、oracle、gold 等仍逐字节校验；
- 已用 `--resume` 重跑，**passed**。

### 2.2 `cve-2020-11002-svc-exploit-real-host` — Harbor gold 0（验收/导出）

最终差分是 passed，但 Harbor gold trial reward 为 0，trial log 只有：

```text
Collecting main service artifacts
```

gold profile 的 `solution/solve.sh` 原本是：

```sh
cp /solution/exploit.py /workspace/exploit.py
```

题目使用了 task-specific main 镜像，镜像里没有 `/workspace` 目录，`cp`
失败，Harbor 收集不到 artifact。已在 `oracle_profile()` 统一加：

```sh
mkdir -p /workspace
cp /solution/<submission> /workspace/<submission>
```

这条修复对所有分支生效，不改变题目语义。已用 `--resume` 重跑，**passed**。

### 2.3 `cve-2024-32613-file-pov` — review rejected（交付质量）

reviewer 的证据：

```text
delivery/private/oracle.sh 的 grep 固定要求
"bytes to the right of 16-byte region"
```

而公开 benign 文件做一次单字段 mutation 后得到 88-byte region，仍然触发
同一 CVE 的 heap-buffer-overflow，但 oracle 返回 1。也就是 oracle 绑定了
gold 的具体大小，而不是公开效果。这是真实的 training-suitability blocker，
不是管线 bug。**不携带**；后续如果重做，需要合成阶段把 oracle 改成
effect-class/region-family 判定。

### 2.4 `cve-2026-24473-svc-exploit-synthetic-host` — review schema（pipeline）

旧校验器报：

```text
ValueError: review.json findings must contain severity and evidence
```

当前 `review.json` 实际包含合法的 `passed/findings/reason/execution_checked`，
`review()` 已兼容旧四字段结构并把它归并成 `passed + evidence`。这是旧代码
误报，已用 `--resume` 重跑，**passed**。

### 2.5 `cve-2026-26983-file-pov` — main.image 不一致（packaging）

```text
task.json.images.agent = linux-066-cve-2026-26983-main:filepov
compose main.image       = linux-userspace-agent:22.04
```

`normalize_delivery_metadata()` 现在会在 main.image 不是 target image 时，
把它规范成 `task.json.images.agent`；如果 main 使用 target image 仍然直接
拒绝（不放宽隔离）。066 已重新 review 并 **passed**。

### 2.6 `cve-2026-32887-svc-exploit-real-host` — runner health 127（交付）

```text
vulnerable health.returncode = 127
argv: runner /opt/pass2fail/runner.py --health
```

runner 复用了 task-specific agent 镜像，镜像没有 `python3`（或
`/opt/pass2fail/runner.py` 的执行环境），health 直接 127。review 通过了，
但没有覆盖到这个运行时缺口。当前没有安全的自动修复：换 shared agent
镜像会改变题目运行时；应由 synthesis 重新产出带 python3 的 main 镜像。
**终态，不携带。**
