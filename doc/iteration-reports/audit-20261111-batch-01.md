## 2. P0 详情

### cve-2022-0144-file-pov — REJECT

`tests/private/oracle.sh:113-131`：

- 以 uid 65534 执行提交物，`2>"$TRACE"`；
- `QUAL=$(grep '^@@SJS_ORACLE_REC@@' "$TRACE" ...)`；
- 只检查记录里的 path/mode，不检查记录由谁写出。

提交物是任意 JavaScript，可以：

1. 读 `/opt/shelljs/src/exec.js` 判断是 vulnerable 还是 fixed（`/opt/shelljs` 是 `a+rX`）；
2. 在 vulnerable 上直接向 stderr 写
   `@@SJS_ORACLE_REC@@{"op":"writeFileSync","path":"<TMPDIR>/shelljs_x","mode":"644","sj":true,"td":false}`；
3. 在 fixed 上不写。

结果：vulnerable oracle 0，fixed oracle 1，reward 1.0，但没有触发 CVE-2022-0144。
review 的“伪造记录会 flip fixed side”只考虑了无 phase-aware 的固定 forge，漏了条件 forge。

**建议**：不要把提交物 stderr 作为证据；用 root-owned pipe/socket/单独 fd，或由 root oracle 直接观察库创建的临时文件。

### cve-2023-51766-svc-exploit-native-service — REJECT

`tests/private/oracle.sh:45-69` 只要求同一条连接里出现 `len(mids) >= 2` 的到达记录；不检查第二封邮件的 envelope 是否来自第一条 DATA 的 injected bytes。

提交物可以：

1. 发送带 `LF . LF` 的 cover message；
2. 后跟 `NOOP`：vulnerable 的 DATA 提前结束，NOOP 得到回复；fixed 不提前结束；
3. 根据 NOOP 回复判断 vulnerable，再发一封普通 `MAIL FROM`/`RCPT`/`DATA`；
4. fixed 上不发。

oracle 看到 vulnerable 两个到达、fixed 一个，reward 1.0；第二封不是 smuggling，而是真实 SMTP 事务。

**建议**：要求第二封 envelope 的 `MAIL FROM` 字节来自第一条 DATA payload，或改判“第一条 DATA 被提前截断”；加 conditional phase-aware 负控。

## 4. 系统性问题

1. **Reference acceptance 只做 gold smoke**：这是有意设计，不要求它证明真实 agent 可解；若要评估训练价值，另做真实 agent solve，不要和 gold smoke 混用。
2. **验收记录以 harbor 证据为准**：不再要求 `acceptance.json`；用 `harbor/result.json` 和 `verifier/evidence.json`。
3. **phase-aware 负控缺失**：多个 CONCERN/P0 的共同根因。review 只测 gold vs benign，需要增加：
   - vulnerable 上 probe、只在 vulnerable 上换非 CVE 路径；
   - fixed 上服务死亡/日志缺失是否被当作 absent；
   - 普通两封邮件、direct DB 写入、任意非管理员行等。
4. **oracle 宽于 instruction**：crash-only、存活-only、任意行/任意文件/计数型 oracle 很多；要么收紧 oracle，要么把 instruction 的效果定义改成 oracle 真正判定的效果。
5. **镜像/构建卫生**：proxy 凭据、fix diff、upstream PoC、seed 数据、合成密码分散在 target/main layer；导出前应做 layer/config 扫描。当前 deep 检查对 target 私有路径/代理凭据能扫到一部分，但 main 镜像的 fix diff/PoC 需要额外人工检查。
6. **instruction 准确性**：多道题有 db/端口/status code/路径/字节数声明不准确；不一定是 hack，但会误导做题者。

## 5. 建议顺序

1. 先修两个 P0：`cve-2022-0144`、`cve-2023-51766`，否则不能进入训练集。
2. 修 `cve-2017-0369`、`cve-2022-35925`、`cve-2024-41954`、`cve-2023-45659` 的 oracle/negative control。
3. 清理 main/target 泄漏：`cve-2026-54782` fix diff、`cve-2020-10177` PoC、proxy 凭据、target 密码/seed。
4. 修 `osv-2022-615` 的 patch/root-cause 或明确收窄为 zero-offset shape。
5. 全批补真实 agent-solve（与 gold smoke 分开）；`acceptance.json` 不再要求。
6. 重新审计 10 道 CONCERN，只有 P1 解决后才算可训练。
